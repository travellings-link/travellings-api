## 小池与故障专项

单站点小池连续访问 30 次均返回 HTTP 200。首次成功后，后续 29 次按明确规则放宽历史并允许重复；前 2 次补采样查询后，额度拒绝的请求仍使用原始批次降级，不继续访问 MySQL。该结果验证可用性选择，不属于“最近 20 次零重复”保证。正常轮换的覆盖边界不适用于已放宽的相关历史或降级请求。

还验证了仅清上一代与全重置两条降级路径、降级结果立即写入当前代及全重置后的成功次数为 1。真实查询异常、非法结果、Redis 故障和关闭不触发历史放宽，也不写失败 Cookie。真实 mysql2 TCP 故障测试确认补采样超时会销毁 socket、淘汰坏连接并可在后续请求恢复；客户端提前断开不跳过补池及补采样的关闭排空。既有 Redis R2–R6 竞态与故障恢复测试继续通过。这些网络/时序故障测试并非真实数据库容量测试。

## 验收范围

- Cookie v3 包含两份 320-bit Bloom、当前代成功次数、`lastId` 和更新时间，不保存 ID 队列。
- 每 20 次成功轮换一代，未触发降级的连续序列在稳态覆盖最近 20–39 次成功事件。降级明确允许窗口内重复，不提供无条件的严格 20 次去重保证。
- 初始候选批次非空且全部被过滤时，最多一次独立 `ORDER BY RAND() LIMIT 64` 补采样。若采样为空/仍全部过滤，或采样预算不足，则优先成功返回，从原始同批先找非上一站且当前代未命中的候选，仅清上一代；否则优先非上一站、清两代并将次数归零，再追加选中结果。单站点允许重复，全重置后次数为 1。
- 查询超时、非法结果、Redis 故障或关闭不触发历史放宽，继续返回 503 且不写 Cookie。补采样未选出不代表真实候选耗尽。指标分别记录尝试、实际降级、历史放宽与全重置。
- 验证 Redis DB 5 候选预取、TTL、原子消费、补池合并与 R2–R6 故障恢复继续成立。
- 真实 mysql2 TCP 故障服务验证补采样超时会销毁 socket、淘汰坏连接，后续请求可恢复；HTTP 客户端提前断开不能跳过已准入采样的关闭排空。
- 88 个 Life 站点、20 个独立用户各访问 50 次，使用真实本地 HTTP/Cookie 流程及模拟存储。测试客户端单独维护最近 20 次日志用于验收，服务不保存该日志。
